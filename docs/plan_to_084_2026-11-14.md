Deadline 17 Nov 2026 00:00 UTC. Nothing in this plan has been run on a GPU yet; every stage has a pass mark and

## 1. What is going wrong (measured on our 270 dev rows)

The job has three steps: decide error or no error, find the line where the root error enters, name it with the code
the teachers would use.

| Step | Measurement | Verdict |
|---|---|---|
| Error or no error | 8 false alarms on 101 correct workings; 12 of 169 errors missed | Minor: about 17 of 50 lost points |
| Find the line | Qwen3.8's root line is within one line of the teacher's on 79% of error rows (Claude 85%) | Mostly solved |
| Name the code | With the right line, Qwen3.8's first code is the teacher's on 64% (Claude 69%) | **The bottleneck** |

- "Right line, wrong code" is 46 rows, about three quarters of Qwen3.8's mistakes on error rows, and 37 of them are a
  different code family. The models see the mistake and label it differently from these teachers.
- Our own fine-tuned models have the opposite profile: they know the teachers' label for a (question, error) pair
  they have seen (0.87) and fail when the pair is new (0.50), because they answer from the question.
- The right code is nearly always within reach on hard rows: in our system's top five, Qwen3.8's three, or the ten
  most similar teacher-marked errors from other questions on **92%** of hard rows (our top five alone 82%, Qwen 70%).
- Published work shows the same pattern: on ScratchMath an open reasoning model explained students' errors well
  (57.5) and classified them badly (13–17) [P7].

**So the problem to solve is: a judge that picks among about a dozen candidate codes the way the teachers would,
given a good description of what the student did.** Nothing we run today is that. The formula that currently
combines our system with Qwen3.8 just multiplies two opinions.

Target arithmetic for 0.84 public (dev-like scores run about 0.04–0.05 above public):

| Row type | Now | Needed |
|---|---|---|
| No error (about 34% of rows) | 0.93 | 0.95 |
| Error seen in training (about 30%) | 0.86 | 0.95 |
| Hard rows (about 36%) | 0.63 | 0.76 |

## 2. What I tested for free and rejected (so it is not in the plan)

| Idea | Result |
|---|---|
| Rerank by re-prompting Qwen3.8 with our shortlist, with and without teacher examples | −0.015 to +0.010 whole-dev; hard rows unchanged |
| Averaging three Qwen3.8 answers | +0.005 |
| A rule for whom to trust when the two systems disagree | −0.009 |
| Simple text model trained on the teachers' written notes to name the code | 64% even from the teacher's own note; −0.005 to −0.019 fused |
| Small learned correction on Qwen3.8's answers (about 216 rows) | −0.014 to −0.022 fused |

Lesson: prompting tricks and small linear models cannot learn the teachers' conventions. It takes a large model
trained on the teacher labels.

## 3. The solution, and where it has worked before

**A trained judge ("ranker v3"): one model that scores each candidate code yes/no for a photo, trained on the
teachers' labels, and given the three things our current ranker lacks.**

| Ingredient | What it is here | Evidence that it works |
|---|---|---|
| Yes/no ranker over candidates | Our ranker v1 already does this with an older 14B model and gained +0.019 dev, +0.015 public | Used by Eedi 1st and 4th and MAP 4th [E1][E4][W4] |
| Reasoning text as extra input | Qwen3.8's own description of the error line and what went wrong (it finds the right line 79% of the time), fed to the ranker | Eedi 1st: private 0.596 → 0.615; Eedi 5th: +0.04 retriever, +0.01 reranker; also Eedi 2nd [E1][E5][E2] |
| Reference examples per candidate code | Teacher-marked examples of each candidate: the same question when one exists, otherwise the most similar marked error from another question | Eedi 1st: 0.495 → 0.531; MAP 4th: examples of each candidate label, CV 0.9480 → 0.9493 [E1][W4]; large models use retrieved examples well on many-label tasks [P5] |
| Candidates from several sources | Our top five + Qwen3.8's three + codes of the nearest teacher-marked errors (92% coverage on hard rows) | Retrieve-then-rerank is the Eedi template for unseen codes [E1][E2] |
| Per-question hints | The codes teachers used on this question, shown as a hint, not a hard mask | Every MAP top-5 solution used the per-question label set [W1][W3][W4][W5]; a hard mask would zero our hard rows, so hint only |
| Bigger, newer backbone | Qwen3.8-27B instead of Qwen3-14B | "Larger was monotonically better from 7B to 32B" (MAP 1st) [W1]; all top solutions 32B–72B [S1] |
| Several seeds | Two or three trainings averaged | MAP 1st: single-seed scores "highly unstable", multi-seed beat multi-fold [W1] |

Why this avoids the known traps:

- The ranker does not need to think. Qwen3.8 does the reasoning zero-shot and the ranker reads it. That avoids the
  finding that answer-only fine-tuning destroys a thinking model's reasoning [P3].
- Qwen3.8's zero-shot outputs on the training rows are honest (it never saw the labels), so the ranker can be trained
  on all 1,500 teacher rows with the same kind of input it will see on test.
- It is our own proven code path (`src/k12/pointwise_ranker.py`), not a new method.

Supporting levers, in order of evidence:

| Lever | Evidence | Expected size |
|---|---|---|
| Run Qwen3.8 at its default maximum reasoning effort (we used medium) | Our run converts to about 0.73 public alone; the host measured 0.757 with the same model, and our prompt reproduces the host's Claude figure | About +0.02 alone; one open 38B model gained 72.3 → 76.0 from a 4K to 16K thinking cap [P2]. Mixed elsewhere, so test on dev first |
| Vote over several Qwen3.8 answers | 1–4 points on modern reasoning models [P1] | Small; only if budget is left |
| Fine-tune Qwen3.8 itself with reasoning + answer | Host: 31B 52% → 64% on 3,400 labels; teacher-written traces were the best option for Qwen3-8B [P3]. Against: VEHME's supervised step alone barely moved [P7]; our 8B attempt failed | Larger but riskier; after the ranker, not before |
| Synthetic examples for unseen pairs, filtered by a judge model | "Crucial" for Eedi 1st; small unfiltered sets did nothing (Eedi 3rd). Our unfiltered catalogue failed | Later, only with filtering |

| D | Qwen3.8 at maximum reasoning effort on the dev rows, then on the test photos where the systems disagree; refresh the ranker's inputs | dev about $1.75; test about $11–18 on the Ada, less on a faster card | Dev: at least +0.04 on the rows it covers | +0.01–0.02 |

Total if everything runs: about $40–50 and about 30 hours of wall time with two pods, inside the time left.
Stages A and B are the core; C and D can run in parallel once B passes.

**What I can and cannot promise.** Each stage is tied to a result someone else has published or we have measured,
and each has a pass mark, so money stops when a stage fails. The targets in the last column are goals, not
measurements: the published gains come from other datasets, and our dev set can only confirm gains of about +0.02
or more.
