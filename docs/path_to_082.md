# Research plan for reaching 0.82 MAP@3

9 November 2026, London time. Our best verified public score is **0.59800**, submission 58133839. The live public top three scored **0.84650, 0.84450 and 0.84150** when checked. Other teams have passed 0.82. CoLearn reported early leaders using open-weight models on Kaggle's free notebook GPUs, but their training recipes and quota consumption are unknown. ## Where the score is being lost

The calibrated model scored **0.60742** on the 301 examples previously used for development. It put 154 correct codes first, 37 second and 31 third. It scored **0.91584** on the 101 `NONE` rows and **0.45167** on the 200 root-error rows. Holding `NONE` performance fixed, those root-error rows would need **0.77160** for the same set to reach 0.82. This points to identifying the error family and root step as the biggest opportunity.

| Candidate source | Correct code in list | What it supports |
|---|---:|---|
| Calibrated image model, top 3 | 73.75% | Even perfect ordering of the same three caps MAP@3 at 0.73754 on these rows. |
| Calibrated image model, top 5 | 82.72% | An almost perfect reranker would be needed to reach 0.82. |
| Calibrated image model, top 8 | 88.70% | A practical starting shortlist. Among error rows alone, coverage is 83.00%. |
| Calibrated image model, top 12 | 92.36% | More room for reranking, with additional candidates to compare. |
| Image top 8 plus the 27B model's top 3 | 91.69% | The models retrieve different correct codes. The union averages 8.88 candidates. |

At 88.70% candidate coverage, 0.82 would require at least 75.30% rank-one accuracy even if every other retrieved correct label ranked second. The current rank-one accuracy is 51.16%. Using the gold label to decide only whether an error exists raises the diagnostic score to 0.67719. Giving the same ranker the gold code prefix raises it to 0.91916 across 35 families, including `NONE`. Both use information available only in labelled data. Some families have a single code, so the family diagnostic gives the model a substantial part of the answer.

Two CPU checks separate the available signal from the oracle results. Fixed reciprocal rank fusion with the saved 27B rankings reached **0.62569**. The paired question-bootstrap interval for its gain is **−0.0153 to +0.0507**, and the 27B run has development predictions only. A new regularized family classifier fitted on 1,199 cached Qwen representations reached **53.82%** family accuracy versus **54.15%** from summing the current model's probabilities by family. Combining them at equal weight scored **0.59468** MAP@3. The useful next experiment is to give the family prediction new evidence from the student's work. [Candidate audit](../reports/path_to_target_audit.json)

The paired model error audit found that **109.67 of the calibrated 4B's 118.17 lost points** came from the 200 root-error rows. It ranked `NONE` first on **51** of those rows and ranked a code from a different error family first on **66**. The frozen 27B reduced the first count to **18** and increased the second to **95**. The 27B retrieved the correct top-three code on **35** of the 4B's misses, while both models missed **44** rows. Combining the 4B's top eight and the 27B's top three reached **91.69%** candidate coverage, leaving **25** root errors outside the candidate set. A router cross-fitted by question scored **0.61794**, below the fixed fusion at **0.62569**. An oracle choosing the better of the two rankings on every row would score **0.74031**. A logistic reranker trained to score individual candidates reached **0.65006** with question-group cross-fitting, including **0.51000** on root errors and **0.92739** on `NONE` rows. The improvement over fixed fusion was **+0.02436** with a paired question-bootstrap interval of **+0.00550 to +0.04284**. This reused development fold cross-fits only the reranker. The next check is to validate candidate-specific visible evidence and expand retrieval for the remaining misses. [Model error audit](../reports/model_error_audit.json)

## Dataset changes worth making

Keep the canonical version-2 labels and images as the source of truth. The 1,500 labelled rows have no duplicate trace IDs, and all root annotations agree with their row's `root_code`. All explicit root-line references resolve. The 3,498 test rows have no train-only fields. One annotation contains a nonstandard JSON `NaN`, which can be mapped to a missing value in a derived parser. Normalizing whitespace and Unicode composition is useful for comparison, while signs, decimal notation, fractions and ordering must survive. The audit found three question IDs with answer-key variants and 88 with grade variation across records. Preserve the context on each row. [Official data description](https://www.kaggle.com/competitions/misconception-detection-in-k-12-student-math-workings/data) · [Dataset audit](../reports/path_to_target_audit.json)

| Finding | Data preparation change |
|---|---|
| 639 possible reading targets and 345 possible explanation targets exceed the prepared 128-token limit. On 115 of 994 root-error rows the first cited line starts outside the reading window. | Create a short root-evidence target that puts cited lines before the explanation. Use overlapping chunks for full transcription and measure target coverage with the real tokenizer. Keep teacher text in training targets. |
| 304 transcriptions mention crossed-out work, 86 mark unclear or illegible text, and 234 rows contain multiple major findings. | Preserve line IDs, deletion markers and uncertainty. Teach the distinction between the annotated root and consequences. Use fitting-row nonroot findings as challenging alternative labels. |
| 57 `NONE` rows have `clean=False`. Thirty correct final answers have an annotated root error, and 19 wrong final answers have `NONE`. | Keep three separate targets for root code, presence of a major error, and final-answer correctness. Use answer checks as evidence with an unknown state when unreadable. |
| 3,348 test rows have a question seen in train. Filtering to labels seen for a question would exclude the correct code on 113 of 262 seen-question development rows. | Use question priors as soft features. Retrieve similar questions and examples from the fitting partition, and retain all taxonomy codes in the candidate space. |
| Thirteen codes have one labelled example. `NOT-02` and `PRO-03` have none. | Start with definition-based candidates and limited targeted augmentation. Measure rare-label recall separately from aggregate MAP@3. |
| The 50,000 unlabeled workings cover 284 questions. Of these rows, 48,808 share a labelled question and 4,261 come from questions with at least one rare training code. | Use a small, diversified pilot pool. A rare training code associated with a question provides a sampling cue, while the teacher still has to diagnose each working. |

A CPU OCR pilot used 60 randomly selected labelled development photos and compared identical images at native size, at a 1024-pixel long side, and with grayscale autocontrast. English Tesseract 5.5.1 recovered **11.69%** of annotated number tokens at both native size and 1024. Math token error was **89.72%** at both sizes and **89.35%** with autocontrast. Only one photo exceeded 1024 on its long side, while 48 exceeded the separate Qwen processor budget of 768 × 768 pixels before processing. These results reject the tested Tesseract recipe as a primary reader and motivate testing the VLM's effective resolution and line crops. The token metric uses limited LaTeX normalization and includes reading-order differences. It measures this English OCR engine on this sample. [Image audit](../reports/cpu_ocr_image_audit.json) · [Target-length audit](../reports/reading_target_audit.json)

On 10 November, the offline CPU pilot compared whole-page Tesseract with Tesseract and PP-FormulaNet-plus-S on 265 automatically proposed regions from those same 60 photos. The formula reader recovered **21.51%** of number tokens, up from **14.15%** with Tesseract on identical crops. Its number precision fell from **49.66%** to **28.74%** under the pilot's token matching, and it exactly recovered **1 of 27** cited equations. The fixed root-example reranker raised Qwen 4B MAP@3 from **0.58611** to **0.59722**, with a paired question-bootstrap interval for the gain of **0.00000 to +0.02632**. Three rows improved and rank-one accuracy stayed at **50%**. With cached 4B and 27B predictions, the formula reader scored **0.65556** versus **0.66389** with whole-page Tesseract. Treat this as a development result. The next screen is to verify candidate-specific equations and keep the original rank when the transcription provides insufficient evidence. ## Approaches to test, in order

| Priority | Approach | First experiment and decision |
|---|---|---|
| 1 | **Retrieve 8–12 codes, then verify the root from the work.** Use the calibrated image model, taxonomy definitions and examples from fitting rows. Score each candidate against the relevant equation, diagram or written line. | Prototype on CPU with the same verifier fed either the official transcript or a machine transcript on the same labelled rows. Compare with the unchanged image score and measure candidate recall, root-error MAP@3 and `NONE` false alarms. The gold transcript is a diagnostic input. |
| 2 | **Specialized math reading.** Compare whole page, overlapping line crops and the supplied question diagram. Use a text reader for Indonesian prose and a formula reader for cropped expressions. | Benchmark a CPU-capable formula model such as PP-FormulaNet-plus-S and a multilingual reader on the same 60 photos. Check number/sign preservation, line order, blanks and OCR that silently repairs a student's mistake. Run the winning view through the diagnosis comparison before using it in a submission. |
| 3 | **Check mathematics with small symbolic verifiers.** Parse supported fractions, signed arithmetic, units and equation transitions. Compare candidate error signatures against what the student actually wrote. | Use gold transcripts first to measure parse coverage and precision for a few frequent confusions. Then feed the same rules machine transcripts and measure the change. Treat unreadable or unsupported expressions as unknown and keep the original image scores as fallback. |
| 4 | **Teach Qwen to locate evidence, then classify.** Train the internal LoRA with a short root-line target, a separate transcription task and close-code alternatives. | If free GPU work is authorized again and admitted under the same cap, compare this objective with the direct classifier on identical partitions. Try a visual-merger adapter only if the reading comparison shows missing visual evidence. The previous full reading run was cancelled in queue and supplies no quality result. |
| 5 | **Add supervision selectively.** Generate controlled misconception variants, such as adding numerators and denominators, and retain mathematically checked hard negatives. Use unlabeled photos for reading consistency or confidence-filtered pseudo-labels. | Measure precision and coverage per family on held-out labelled work before using a teacher. Start with hundreds of verified pseudo-labels and compare against the same training recipe without them. Balance by question and grade, and avoid duplicating the teacher's easiest `NONE` predictions. |
| 6 | **Combine complementary evidence.** Blend calibrated image and text-verifier scores after measuring both. Try multiple crops or candidate-order reversal for uncertain rows. | Screen marginal gains on the same IDs and reserve an independent check. Existing head adapters, text-only question priors and the fixed family-head blend offer little reason to spend more time on them. Full 27B inference at its measured 301-row rate would take about seven hours for 3,498 images, before setup. |

The first experiment isolates a concrete choice. A strong result with gold transcripts and a weak result with machine transcripts points toward reading. Weak results with both point toward diagnosis and code distinctions. The old gold-transcript TF-IDF classifier scored only **0.53544** on these same 301 rows, so text access by itself did not solve the task. Use a verifier that evaluates competing explanations with line evidence and structured math checks.

The proposed shortlist coverage goal is at least **90%** at a manageable candidate count, followed by a substantial increase in root-error ranking. This is an engineering target. Freeze the recipe before the final check, group related examples during validation, and report performance on seen and unseen questions, rare labels, diagrams and ambiguous handwriting. The existing Qwen checkpoint trained on fold 4, so an image-model audit on that fold requires a fit that excludes it. Keep any comparison based on existing fold-0 outputs labelled as exploratory.

## What transfers from public work

- **Competition notebooks.** Hanh Tran's baseline shows a real OCR and reranking route, with its published public score around 0.597. The source and logs expose OCR truncation and runtime problems. Samanyu's pseudo-label notebook uses gold transcription during part of training and generated transcription at inference, so compare matched inputs before attributing a gain to pseudo-labels. The newer Rishabh notebook combines priors with submissions from other notebooks. Its source alone does not establish an independently trained reader. [Hanh Tran](https://www.kaggle.com/code/honghanhhh/k-12-baseline-lb-0-597) · [Samanyu](https://www.kaggle.com/code/samanyu1808/misconception-vlm-pseudo) · [Rishabh Bafna](https://www.kaggle.com/code/rishabhbafnaiiitd/misconception-detection-in-math-working)
- **Claims to check against executed code.** The public clean-gate notebook simulates confidence from known clean flags with random draws and supplies fixed mock error candidates. The pipeline notebook falls back to the question as if it were student work. Neither computation validates a reader or evidence-based test gate. [Clean-gate source](https://www.kaggle.com/code/vijaikm/k12-math-clean-gate-postprocessing-masterclass) · [Pipeline source](https://www.kaggle.com/code/vijaikm/k12-math-top-rank-champion-eda-and-pipeline)
- **Handwriting research.** FERMAT and ScratchMath separate image recognition, error localization and reasoning. A later OCR study shows why transcription fidelity matters when a model automatically corrects the math. Compare symbol preservation and downstream ranking on this dataset. [FERMAT](https://arxiv.org/abs/2501.07244) · [ScratchMath](https://arxiv.org/abs/2603.24961) · [OCR over-correction study](https://arxiv.org/abs/2604.22774) · [PaddleOCR formula models](https://www.paddleocr.ai/main/en/version3.x/module_usage/formula_recognition.html)
- **Training and retrieval.** CoLearn's separate gold-text benchmark reports gains from task-specific fine-tuning. The Eedi second-place write-up supports definition expansion, validated synthetic data and shortlist reranking on a different task. Process supervision and confidence filtering provide templates for training from the available line annotations and unlabeled pool. These sources motivate experiments on K-12 and have different evaluation conditions. [CoLearn fine-tuning](https://colearnlab.com/training-llms-to-identify-student-misconceptions-from-their-written-work/) · [Eedi GitHub solution](https://github.com/wangqihanginthesky/Eedi_kaggle/blob/main/Solution.md) · [Process supervision](https://arxiv.org/abs/2305.20050) · [FixMatch](https://arxiv.org/abs/2001.07685)

Kaggle permits accessible external data and models subject to the host's rules and licensing. Final inference must be reproducible offline. Keep student work private and avoid human prediction on test rows. MathWriting's data uses a noncommercial share-alike license and covers individual expressions, so it is outside the current plan. Prioritize the organizer's data and verify the license of each specific checkpoint before adoption. ## Reproduction

`scripts/audit_path_to_target.py` reads the canonical CSVs and saved development rankings. Its `--unlabelled`, `--feature-cache` and `--tokenizer` options reproduce the pool, family-head and target audits. The feature branch uses scikit-learn and the tokenizer branch uses the saved Qwen tokenizer and the local training module. `scripts/audit_cpu_ocr.py` selects 60 fold-0 rows with seed 2026 and reads their official training JPEGs from the private `data/cpu-image-audit/` directory. Each output is an aggregate report. No test photo or student text is included in the reports.
