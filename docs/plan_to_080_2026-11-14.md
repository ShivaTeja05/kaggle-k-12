# Plan to reach 0.80 public

Written 14 November 2026, about 08:50 UTC. A plan only: nothing in it has been launched or approved. It assumes money
is not the limit, as the owner said; wall-clock time (deadline 17 Nov 00:00 UTC, about 63 hours) and one
engineer-agent's attention are. Sources: read-only CPU measurements on saved dev answers (this session), web research
on current open models and on fine-tuning Qwen3.8-27B, a read-only audit of the code, and an independent red-team pass.
The model facts below come from that web research on 14 November and should be re-checked on the model cards before
a pod is rented.

**Terms.** "Dev" is the 301-row development fold; dev has run about 0.018 above the public score for the current
system, so 0.80 public needs about 0.82 on dev. "M" is our fine-tuned small-model system (0.755 on dev alone).
"Reasoner" is a vision-language model that reads the photo with thinking on. "Sent rows" are the least-confident
rows that go to the reasoner (158 of 301 on dev, 1,593 of 3,498 on test).

## 1. What 0.80 requires (measured)

Dev, 301 rows, cross-fitted. Rows marked "stand-in" use Claude's or Fable's saved dev answers in place of an open
model, only to size the effect; they cannot be used at test time.

| Reasoning side fused with M | Dev |
|---|---|
| Qwen3.8-27B (today; public 0.76266) | 0.780 |
| + a text-only reasoner on our transcript, 0.786 alone (stand-in) | 0.798 (+0.019 [+0.001, +0.037]) |
| + a second photo model, 0.804 alone (stand-in) | 0.809 (+0.029 [+0.009, +0.050]) |
| A reasoning side at Claude-with-photo level, 0.823 alone (stand-in) | 0.816 to 0.819 |

- When two reasoners agree on the top code they are right 80% of the time; when they disagree each is right 25 to 36%. An extra independent opinion is what the disagreement rows lack.
- No single open lever measured so far supplies the +0.04 needed. Two of the levers below have to land together.

| 4 | Fine-tune Qwen3.8-27B with thinking kept, on Claude's existing reasoning for the 1,199 fit rows plus 3,000 to 4,000 filtered pool rows; serve merged weights | +0.020 to +0.045, can be negative | 20 to 25% | 20 to 28 | $100 to $200 |
| 5 | Per-question prior from the reasoners' answers on the other test rows of the same question (CPU) | +0.005 to +0.015 | 30% | 2 | none |

Not worth running: a text-only reasoner (the same large models see more with the photo), pseudo-label retraining of
the old classifiers, scoring the confident half of test, a new pointwise ranker, fine-tuning on self-generated chains.

Why lever 3 moved up. The host said in October that the leading teams (0.815 to 0.823 then) used open models that
fit Kaggle's free GPUs, which rules out 2,400 thinking tokens per photo and points to answer-only fine-tunes of
current-generation models. The host's own study found fine-tuning worth 7 to 18 points. Every classifier we trained is
the older Qwen3 generation (0.65 alone); Qwen3.8-27B without thinking is already 0.657 untrained.

## 3. Tracks

All tracks start at hour 0 once approved. Fusion settings stay frozen; the reasoner side is the unweighted mean of
rank shares over admitted reasoners.

| Track | Steps | Gate to go on to test scoring |
|---|---|---|
| A. Votes | Score Stage 1 when it ends (about 10:49 UTC). Run Qwen3.8 samples 2 and 3 on all 158 sent dev rows, including the 23 that timed out. Then the same on the 1,593 sent test rows. | Dev screen: at least +0.005 with hard rows not negative. Confirmed only by the public score (+0.004 or more). |
| B. Second reasoner | Start Qwen3.8-Flash-Next (4 large GPUs) and Gemma 4 31B (one 80 GB card) together. Each answers the sent dev rows; after a 20-row sanity read the same loaded server continues to the test rows. | At least 95% valid answers; alone no more than 0.05 below Qwen3.8 on the same rows; fused gain at least +0.015 on dev. Total model size including M under 550B. |
| C. Classifier fine-tune | Patch the LoRA targets for the model's Gated DeltaNet layers, switch thinking off explicitly, 8-row smoke test in full precision. Then a dev-fold run and a full-data run in parallel. | Smoke: at most about 4 s per row. Epoch 1: dev at least 0.60. Final: alone at least 0.70 and fused gain at least +0.015, no-error rows not down by more than 0.01. |
| D. Thinking fine-tune (stretch) | Build the training file from Claude's saved reasoning; one epoch; merge; serve merged. Two adapter scales only (0.5 and 1.0). | Starts only if track C's smoke shows the architecture trains at usable speed. Training must start by hour 24, test scoring by hour 48. Dev: alone +0.03 over zero-shot, fused +0.02. |
| E. CPU and the close | Question prior (lever 5). Reproducibility manifest for every added model. No new arms after hour 52; last submission at hour 56. | Question prior: +0.010 on dev, then one public confirmation. |

**Stop rules.** A reasoner that is not serving image requests within 3 hours of pod creation is dropped. A step that
lowers the public score by 0.005 or more is removed from all later files. The rerank prompt is adopted only at +0.025
with the range above zero. The thinking fine-tune gets no second training run.

**Final selection.** Two files: the best public file, and the best file containing only steps confirmed on both dev
and the public board.

## 4. Odds (estimates, not measurements)

| Public score | Chance |
|---|---|
| 0.78 or better | about 60% |
| 0.80 or better | about 20 to 25% |
| 0.82 or better | about 3 to 5% |

Expected finish about 0.785 to 0.79. Reaching 0.80 needs two of these three to land together: a second reasoner near
Qwen3.8's quality, the classifier fine-tune adding +0.015 or more, or the thinking fine-tune working first time.

## 5. Risks

- No open model is measured at Qwen3.8-27B's level on this task. The second-reasoner track may give only +0.01.
- Dev is small (paired standard error about 0.013) and already heavily used; this plan adds 8 to 10 arms. The public board (13 submissions left: 3 today, 5 and 5) is the confirming test, and it is itself only 29% of the test set.
- One engineer, four tracks. Each new model is a new serving recipe; each fine-tune is new code on an architecture never trained here. Adapters for this architecture are reported to misbehave in vLLM unless merged.
- Pod stock for 4 to 8 large GPUs is not guaranteed the same day; downloads are 186 to 306 GB; the Mac's upload speed and nearly full disk slow the training-photo upload.
- Offline and reproducibility: every member must be open-weight, version-pinned and counted under 550B with M. Qwen3.8-Flash-Next has a non-standard licence; check the competition's licence rule before relying on it.
- The record is silent on whether the host allows using unlabelled test rows for a prior (lever 5). It is not hand-labelling, but ask the host if a prize comes into reach.
